# Dedup experiment: findings and recommendation

Run on 2026-09-29, branch `feature/beir-harness`. Full tables: `results.md` (generated by
`analyze.py`). Pipeline: RRF + Ettin 32M, 100→40→20, 1,200-character chunks,
nomic-embed-text v1.5; dedup runs after RRF, before the 40-candidate shortlist. Baselines
reproduce earlier runs exactly (SciFact 0.73252, NFCorpus 0.34269).

## Recommendation

**Leave the pipeline as is. Do not ship B or D. Keep C (near-duplicate) as an experiment
to revisit only if a real document library turns out to contain many near-copies.**

- **B (exact text)** does nothing on real corpora: they contain almost no exact duplicate
  chunks, because ingestion already merges byte-identical documents (0 in SciFact, 1 in
  NFCorpus, 27 in ArguAna's 11,564). Even on the duplicate-injected corpus it removed the
  exact repeats but barely changed what was retrieved (distinct-relevant recall +0.2 points,
  p = 0.75).
- **C (near-duplicate)** is the only variant with a real effect, and only where duplicates
  exist. On scifact-dup it cut duplicate documents in the top 10 from 12.3% to 5.4% and
  raised distinct-relevant recall at k = 5 by 1.6 points (p = 0.052, 8 queries better,
  1 worse). At k = 10 there was no gain (−0.2 points). No change on SciFact or NFCorpus.
- **D (≤ 2 chunks per document)** changed almost nothing anywhere (all differences ≤ 0.003
  nDCG@10, none significant), although about 15% of top-10 chunks share a document with a
  higher-ranked chunk.
- **Cost:** none measurable. Seconds per query were the same within noise for every
  variant.

## Why the standard metrics look worse for C

On scifact-dup, C's nDCG@10 fell by 0.105 and B's by 0.018. That is expected and not a
retrieval loss: the injected copies are judged relevant under their own IDs, so removing a
copy removes a "hit" even though the same content is still retrieved. Distinct-relevant
recall, which counts each duplicate group once, is the fair measure there.

C also lowered ArguAna nDCG@10 by 0.019 (p = 0.0015, 3 better / 14 worse). In 12 of the 14
worse queries the "lost" relevant argument was replaced by a 96–100% identical copy of the
same argument posted in another debate category (e.g. `test-environment-assgbatj-con04b` vs
`test-science-eassgbatj-con04b`); ArguAna's judgments only label the copy in the query's own
debate. The remaining 2 were small reorderings within the top 10. So that drop is a
labelling artefact, as the handoff anticipated.

## Caveats

- scifact-dup's copies are synthetic (an appended note, one reversed word). Real revisions
  may differ more, and 5-word-shingle Jaccard ≥ 0.9 misses copies with more edits.
- Near-dedup keeps the higher-ranked copy, not the newest. In a library with revisions it
  could hide the current version of a document; shipping it would need a rule for which copy
  to keep.
- ArguAna was a 300-query sample (seed 42); the other sets used all queries.
- Metrics are at document depth 5 and 10 from 20-chunk requests, not separate topK = 5 and
  topK = 10 pipeline runs.

## Next step if revisited

Measure the duplicate rate on a real document library first (the analysis's chunk
duplicate columns need no relevance judgments). If near-duplicates make up a meaningful
share of top-k results there, test C with a "keep the newest copy" rule.
